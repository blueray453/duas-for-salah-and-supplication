Text layout: what a font can and cannot tell you

Important: a font file does not contain the complete identity of the Qur'anic text being rendered. This report tests glyph coverage and OpenType shaping/positioning, and gives a cautious role classification for each supplied font. It cannot infer the rasm or riwayah of an unseen text string.

Why Sunnah.com recommends KFGQPC Uthman Taha Naskh

Sunnah.com's Fonts note recommends this font, but explicitly says any Arabic font with a complete set of ligatures will do. It specifically calls out Unicode character ﷺ (U+FDFA). This is an Arabic prose/hadith rendering requirement, not a requirement that the font contain all Qur'anic pause marks.

The supplied KFGQPC Uthman Taha Naskh file meets the key observable requirements: it maps U+FDFA; its GSUB table includes Arabic contextual-form/ligature features (init, medi, fina, liga, calt); and its GPOS table includes cursive and mark positioning (curs, mark, mkmk).

Its metadata reports 637 glyphs but only 293 Unicode cmap mappings. These figures are not contradictory: many glyphs are contextual forms, ligature outputs or alternates reached through OpenType shaping rather than separate Unicode characters. A low cmap count is not a reliable font-quality ranking.

The earlier report made a test-target mismatch: it scored this Naskh font against pause marks that Sunnah.com does not name as its requirement. For Sunnah.com's stated use case, the font is a reasonable match. For Qur'anic Hafs text with the six Madinah pause marks, use a Qur'anic/Hafs font such as the supplied UthmanicHafs_V22.ttf or AmiriQuran.ttf, then verify the exact source text and visual rendering.

Feature tags are technical evidence, not a complete quality score. Actual text sequences still need visual review in the target browser.

Pause marks: the full Madinah set

Tanzil documents six Madinah Mushaf pause-mark classes. The set is represented by six distinct code points; the interchangeable-pause mark appears twice in its real example. A separate Saktah sign (U+06DC) is also tested below because it matters in Hafs reading but is not one of Tanzil's six listed classes.

Suggested font selection by content type

Use different faces for different content. Do not select one font solely because it wins the largest Unicode count.

/* Hadith / ordinary Arabic prose: Sunnah.com-style use case */
.hadith-arabic {
  font-family: "KFGQPC Uthman Taha Naskh", "Amiri", serif;
}

/* Qur'anic Hafs text with Madinah pause annotations */
.quran-hafs {
  font-family: "Uthmanic Hafs V22", "Amiri Quran", serif;
}

/* Standalone honorific in a separate element */
.honorific {
  font-family: "KFGQPC Uthman Taha Naskh", "Amiri Quran", serif;
}

Define each @font-face using the supplied file names. Keep text in lang="ar" dir="rtl" containers. Do not assign an Indo-Pak font to Uthmani text unless the source's orthography and marks are compatible.

Fallback is relatively safe for a standalone symbol like U+FDFA. Fallback across combining marks in the middle of an Arabic word can produce mismatched placement, so visually validate it and prefer a single font that covers the complete target text.

How to interpret this report

  • Font inventory scope: the binary audit covers the 54 TTF/OTF files in the original user-supplied archive. No external font binary was silently added. External references are used to explain categories and intended use.
  • Unicode cmap: confirms a direct character-to-glyph mapping. It does not count every glyph available through shaping substitutions, nor prove that a glyph is well drawn.
  • Glyph count vs cmap count: total glyph count includes internal contextual forms, ligature outputs and alternates; cmap count measures characters directly mapped by Unicode. Do not compare these as one coverage score.
  • GSUB/GPOS: GSUB replaces glyphs (for example, contextual Arabic forms and ligatures); GPOS positions glyphs and marks. Feature tags are useful evidence, not a complete font-quality metric.
  • Text identity: rasm/orthography and riwayah belong to the source text/edition. A font name cannot establish that arbitrary text is Uthmani, Imla'i, Hafs or Warsh.
  • Page layout: 15-line Madani, 15-/16-line Indo-Pak and similar formats require page/line metadata. Ordinary Unicode fonts do not store the full layout.
  • Fallback: a browser may display missing characters from another font. Coverage results always refer to the selected font's own cmap.
  • unicode-range: tells the browser which characters a font face may supply. It cannot add a glyph absent from the font.
